### 시나리오 1: 토큰 미설정 상태에서 내보내기

**재현 방법**:
1. `~/.discord-exporter/config.json`에서 token 삭제 또는 파일 삭제
2. GUI 실행
3. 채널 URL 입력: `https://discord.com/channels/123456789012345678/987654321098765432`
4. "내보내기 실행" 클릭

**예상 결과**:
- [ ] 토큰 입력 팝업이 자동으로 표시됨

- [ ] 토큰이 화면에 평문으로 노출되지 않음

### 시나리오 3: 잘못된 채널 URL 입력

**재현 방법**:
1. Discord URL 입력란에 다음 중 하나 입력:
   - `https://google.com/channels/123/456` ← 아래 주의사항 참조
   - `https://discord.com/channels/123`
   - `https://discord.com/channels/abc/def`
   - `discord.com/channels/123/456` (http:// 없음)
2. "내보내기 실행" 클릭

> **⚠️ 주의 (코드 동작 기준)**:
> `gui.py:_on_parse_url`은 `"discord.com/channels"` 포함 여부로 파싱 진입을 결정합니다.
> - `https://google.com/channels/123/456` → 포함되지 않아 **조기 반환** → `lbl_export_target` 미변경 (URL 오류 표시 없음)
> - 나머지 3개 케이스 → `parse_discord_url_extended()` ValueError → `"URL 오류"` 인라인 표시
>
> `"URL 오류"` 표시 테스트 시에는 **discord.com URL 케이스** (`https://discord.com/channels/123` 등)를 사용하세요.

**예상 결과**:
- [ ] `lbl_export_target`에 `"URL 오류"` 빨간색 인라인 표시 (다이얼로그 없음, `gui.py:_on_parse_url`) — `https://discord.com/channels/123` 등 discord.com 케이스에 한함
- [ ] `https://google.com/channels/123/456` 입력 시 lbl_export_target 미변경 (조기 반환)
- [ ] 로그에 별도 메시지 없음 (URL 오류는 인라인 표시만)
- [ ] 이후 "내보내기 실행" 클릭 시 E4 다이얼로그 표시 ("내보내기 대상이 없습니다.\nDiscord URL을 입력하거나 채널을 체크해주세요.") — 모든 케이스 공통

### 시나리오 4: 잘못된 채널 ID 입력

**재현 방법**:
1. 채널 ID 입력란에 다음 중 하나 직접 입력:
   - `12345` (너무 짧음)
   - `abc123456789012345678` (문자 포함)
   - `123456789012345678901234567890` (너무 김)
2. "내보내기 실행" 클릭

> **⚠️ 주의 (코드 동작 기준, 2026-07-11 Doc-Sync 21차 확인)**:
> `utils.py:validate_channel_id()`는 숫자 여부를 길이보다 먼저 검사합니다
> (`isdigit()` 체크 → 길이 체크 순서). 따라서 입력값에 따라 서로 다른 메시지가 표시됩니다:
> - `12345` / `123456789012345678901234567890` (길이만 문제, 전부 숫자) →
>   `"채널 ID 오류: Channel ID should be 17-20 digits, got N digits"`
> - `abc123456789012345678` (문자 포함) →
>   `"채널 ID 오류: Channel ID must be a number, got: abc123456789012345678"`
>   (길이 체크에 도달하지 않음)

**예상 결과**:
- [ ] 숫자만 있으나 길이가 17-20자 범위를 벗어난 경우: "채널 ID 오류: Channel ID should be 17-20 digits, got N digits" 에러 표시 (gui.py가 영문 ValueError를 "채널 ID 오류: " 접두어로 래핑), 입력된 길이 정보 포함
- [ ] 문자가 포함된 경우: "채널 ID 오류: Channel ID must be a number, got: {입력값}" 에러 표시 (길이 메시지 아님)

### 시나리오 7: 존재하지 않는 DCE 경로

**재현 방법**:
1. config.json의 dce_path를 존재하지 않는 경로로 수정:
   ```json
   {
     "dce_path": "/path/to/nonexistent/DiscordChatExporter.Cli"
   }
   ```
2. GUI 실행
3. "내보내기 실행" 클릭

**예상 결과**:
- [ ] "DCE 파일을 찾을 수 없습니다" 에러 표시
- [ ] "파일이 이동되었거나 삭제되었는지 확인하세요" 안내 포함
- [ ] "'찾아보기' 버튼으로 올바른 경로를 선택하세요" 안내 포함

### 시나리오 8: DCE 실행 권한 없음 (macOS/Linux)

**재현 방법**:
1. DCE 파일의 실행 권한 제거:
   ```bash
   chmod -x /path/to/DiscordChatExporter.Cli
   ```
2. GUI 실행
3. "내보내기 실행" 클릭

**예상 결과**:
- [ ] "DCE 파일에 실행 권한이 없습니다" 에러 표시
- [ ] `chmod +x "/path/to/file"` 명령어 안내 포함
- [ ] 권한 복구 후 정상 동작 확인

**테스트 후 정리**:
```bash
chmod +x /path/to/DiscordChatExporter.Cli
```

---

### 시나리오 9: 출력 폴더 쓰기 권한 없음

**재현 방법**:
1. 쓰기 권한 없는 폴더 생성:
   ```bash
   mkdir /tmp/readonly_folder
   chmod 555 /tmp/readonly_folder
   ```
2. GUI에서 출력 폴더로 `/tmp/readonly_folder` 선택
3. "내보내기 실행" 클릭

**예상 결과**:
- [ ] "폴더에 쓰기 권한이 없습니다" 에러 표시
- [ ] "다른 폴더를 선택하세요" 안내 포함
- [ ] chmod 명령어 안내 포함

**테스트 후 정리**:
```bash
rm -rf /tmp/readonly_folder
```
